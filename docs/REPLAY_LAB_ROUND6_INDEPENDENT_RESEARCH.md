# Replay Lab — Round 6 Independent Research: Architecture, Evidence, and Feasibility

**Research completed:** 17 November 2026. **Author:** ChatGPT / GPT-6. **Status:** research only; no replay files uploaded to models, no API calls billed, no application code modified, and no final architecture decision. Compare this with Claude, Gemini, Antigravity, and the project owner's review BEFORE implementation.

**Start here:** [Project Compass](replay-lab-project-compass.md). **Evidence:** current GitHub source on PRs #16, #20, #22, #24; official Rocket League and Gemini API documentation; external original project repositories/docs. External model metrics are authors' reports, not independently reproduced on Replay Lab.

## 1. Executive finding

**The core bottleneck is NOT reconstructing positions, identifying the next toucher, creating a realistic 3D renderer, or possessing a general-purpose LLM. The bottleneck is VALIDATED STRATEGIC DECISION VALUE.** Our physics says which touches are plausible; it does not establish whether an aggressive challenge has positive possession, pressure and recovery value compared with shadowing. Current tactical judgments still include uncalibrated thresholds; a sentence generated by Gemini does not make those judgments true.

Recommended **first experiment**: local 2v2 replay -> frozen t0 evidence -> candidate feasible actions and key uncertainties -> two independent reasoners/baselines -> blinded review by experienced players of strategic value and explanation. Add actual native gameplay frames ONLY to test whether they improve a contested mechanical/possession claim. Evaluate on held-out MATCHES, not thousands of correlated frames. Use optional native Rocket League playback where it works; do not block the coach on pixel-perfect browser replication.

Recommended **longer-term architecture to test**, NOT yet adopt: typed event/provenance graph + robust feasibility ranges + learned calibrated possession/goal-pressure primitives (where justified) + human-ranked action preferences + constrained LLM reasoning and dialogue, with user correction and lifelong optional player profiles. A large locally trained LLM/5B video world model is not a rational first investment.

## 2. Verified gaps in our own code — not another generic audit

1. **Selected Gemini moment is not used to select frames.** In `coach-app/coach_app/main.py` on PR #24 the /api/ai-review handler accepts a selected_time, describes a roughly +/-3-second window, but calls `compact_game_states(payload.replay, payload.player_id, max_frames=90)`. In `coach-app/coach_app/coaching.py`, that function STRIDES through the entire `replay['frames']` array rather than slicing near selected_time. This can deprive the LLM of its intended tactical window while misleading the prompt about what it received. Proven by source, NOT by an API response. Any first experiment should correct evidence selection and explicitly identify each timestamp and packet's validity.
2. **Two separate coaching worlds, not an intelligent tutor.** The old endpoint is a one-shot, one-hypothesis numeric-text prompt; Claude's PR #22 `decision-cases` and `coach-question` use richer deterministic evidence, but the natural-Q&A helper is not a tool-calling LLM on the main front end. A joined, source-validated tool layer is missing.
3. **Reachability vs tactical merit.** PR #22 reports from 15 public, unknown-rank 2v2 replays a reduction in touch lower-bound violations from 27.6% to 5.7% and an improvement in first-touch ranking 59.6% to 67.4%. These are SOURCE-REPORTED benchmark results, not independent replications and not 2v2 tactical accuracy. Some assumptions were tuned and tested on the same replay group. `defender_decisions.py` uses unvalidated 0.3-second contest and 1.0-second cover windows. Missing/finite boost and missing positional fields create specific edge-case errors already noted on PR #22.
4. **No proof of native per-actor source time.** Our `subtr_replays.py` normalizes resampled ndarray frames and assigns a common row time. The `evaluation/packet_freshness.py` audit correctly refuses to certify native packet freshness. Treat interpolation as playback-only unless source provenance is independently recovered.
5. **Text citation != justified conclusion.** PR #22's `coaching_qa.validate_answer` can be confused by mixed t0 and retrospective citations and by malformed JSON item shapes. A model must give claim-level typed references with programmatic temporal gate and a separate semantic verification step; a text regex alone cannot enforce a counterfactual's causal correctness.
6. **Missing human truth.** PR #16 has a 40-clip choice/commitment TIMING study and separate tactical merit Stage 1/2 protocol, but no expert judgments or legitimate actual gameplay clip exports. Antigravity PR #23's claimed clip exporter contains one dummy WebM frame; the PR #16 ffprobe integrity gate correctly fails closed on this placeholder. Important to keep the studies separate.
7. **Native API research is NOT new.** Correct official socket command schemas were previously developed in PR #20, but local game round-trip and camera/seek sync have not been verified. The official Stats API outputs match status and spectator shortcut IDs; it does not grant a direct browser render surface.

## 3. Research discoveries outside our repository

### A. Public high-level 2v2 replay dataset — high priority DATA AUDIT

The [Rolv-Arild high-level replay dataset](https://github.com/Rolv-Arild/rl-high-level-dataset) states a curated collection of **49,658 2v2 matches**, along with 48,435 1v1 and 42,235 3v3 matches. It describes GC+ discovery, SSL/pro relationship scoring, anti-bot/handicap filtering, gameplay-duration balancing and a [Kaggle dataset](https://www.kaggle.com/datasets/rolvarild/high-level-rocket-league-replay-dataset).

**Status:** repository documentation verified online; files, exact replay-level rank correctness, playable sample, size, platform IDs, redistribution terms and coverage across patches **not independently audited**. The repository did not expose a license in the inspected listing. Do not claim blanket permission to copy the dataset into our public GitHub repo. Sample its metadata and a few files under permitted usage, reconcile all four player tracks, inspect novel modes/patches, and see whether high-rank inclusion rules actually hold.

What it can offer: high-level **behavior distribution, common choices, feasible teammate rotations and retrieval candidates**. What it cannot establish: these actions were globally optimal, a bad decision was not made, or their outcome is a causal counterfactual for our player.

### B. Existing value/possession modeling — a plausible SMALL learned-model track

The [sab-rl-metrics project](https://github.com/ch-lum/sab-rl-metrics) builds a **three-class Advantage A / Neutral / Advantage B** classifier rather than naive last-touch possession, pre-/post-shot expected-goals models, per-touch possession-value change, and a frame-level future-goal hazard model. Its authors report 108 training / 27 held-out games for some experiments, e.g. 5-second goal-probability Brier skill ~0.140 vs constant-rate and ~1.6-second median prominent warning before scoring. Their README also documents serious parser/velocity/boost issues and strict distinction between PRE-shot vs POST-shot features.

**Status:** real public code and reports found, results author-reported and not independently replicated, small and potentially skewed tournament set, some metrics conditional on detected shot events. A probability of a goal in the next 5 seconds is **not the value of our alternative action**. But using a calibrated state-threat estimate could be a more honest comparison feature than a free-form story about "high chance" or guaranteed possession. Possession labels and parser checks are worth reviewing even if we never reuse their model code.

The [subtr-actor Python library](https://github.com/rlrml/subtr-actor/blob/master/python/PYTHON-README.md) already exposes `get_replay_frames_data` (no fixed-FPS resampling) and optional `expected_goals` event/stat tracks. This is a concrete source-provenance and model-baseline lead. Native update time may STILL require reading raw actor deltas; an unresampled frame is not by definition a per-car fresh update. Existing expected-goals implementation/training/calibration must be inspected before treating its number as ground truth.

### C. Learned RL policies and video world models have a narrower role

[RLGym](https://rlgym.org/Getting%20Started/quickstart/) provides 2v2 RocketSim environments and PPO training examples. These are genuine policy/reward learning mechanisms, but bot reward optimization and human skill/style explainability are different evaluation targets; default training configuration is not an SSL-quality human coach, and large-scale training is expensive.

[EARL](https://github.com/Rolv-Arild/EARL-pytorch) is an entity-attention Rocket League representation with next-goal and action-prediction examples, not verified tactical judgments. [A 3v3 RLCS goal predictor](https://github.com/dster2/rocket-league-goal-predictor) is open-source with a reported ~1.8M-parameter transformer and ONNX inference, but explicitly targets **3v3**, not our 2v2 objective.

[MIRA](https://github.com/mira-wm/mira), a 2026 5B-parameter 2v2 video world model, publishes code and a synchronized multi-player **bot self-play** dataset with videos, controller actions and physics. Potential uses: camera/action synchronization research and synthetic scenario visualization; NOT evidence of human high-rank coaching, nor proof of correct physical consequences on arbitrary human replays. A five-billion-parameter local video simulator should not precede a small expert-validated coaching slice.

[MHR Rocket behavior-style paper](https://arxiv.org/abs/2502.14998) models individual action styles for 2,000 Rocket League participants. Inspect exact game mode/data before transfer. It does not demonstrate 2v2 optimal-decision coaching or long-term style inference from a few of our matches.

### D. Native game and Gemini official capabilities

The [official Rocket League Stats API](https://www.rocketleague.com/developer/stats-api) documents local TCP/WebSocket update streams and replay commands `LoadReplay`, `SeekReplay`, `ChangePOV`, `SetMatchPaused`, `SetGameSpeed` and HUD toggles. It exposes replay Frame and Elapsed in UpdateState, plus player spectator Shortcuts, but not a direct video stream. The actual game remains a separate application until a window-capture bridge is built and measured. Native use needs local opt-in configuration and a client restart; PR #20's transport/schemas are a prior partial implementation, not validated game control.

The official [Gemini function-calling docs](https://ai.google.dev/gemini-api/docs/function-calling) support serial and parallel function calls; our app must execute and authorize each tool. The [video understanding docs](https://ai.google.dev/gemini-api/docs/video-understanding) say static video starts at ~1 FPS and supports custom sampling, with some Flash models supporting agentic video exploration. A 1 FPS view can miss fast challenges; video is useful for targeted mechanics questions only with controlled time alignment, frame density and true recorded gameplay.

The official [pricing page](https://ai.google.dev/gemini-api/docs/pricing) lists Gemini 3.8 Flash standard paid input **$0.75/1M** and output/thinking **$3.75/1M** until Dec 31, 2026; Jan 2027 pricing increases. These are listing prices, not cost of our product. A *hypothetical* 10k input + 2k output-token request would cost around **$0.015** before retries, video tokens, tool loops, caching, taxes, changing plans and hidden thinking/output variability. A 3-call 5-moment analysis might start around ~$0.225 on that artificial assumption, not a measured production invoice. No paid calls made.

[ballchasing.com's API documentation](https://ballchasing.com/doc/api) confirms searchable replays and authenticated download limits; for a standard non-patron account, the docs list **50 other-users' replay downloads/day**, in addition to per-second/hour limits. Confirm dataset/consent/attribution and do not download redistributable private replays blindly.

## 4. Architecture choices — deliberately no winner yet

| Candidate | Promising capability | Primary failure/unknown | Decision now |
| --- | --- | --- | --- |
| Current heuristic verdicts + richer reach | Fast, interpretable feasible states and first/second-man geometry | Arbitrary tactical thresholds and missed off-ball context | Baseline; keep, do not overclaim |
| General LLM over whole replay text | Flexible, natural teaching | Context dilution, invented evidence/possessions, future leakage | Do not use alone |
| **Evidence-frozen tool-using LLM** | Iterative precise inquiries, compare actions, field grounded follow-up | May rationalize bad decision model; needs semantic validation and expert truth | **Preferred experiment**, not accepted architecture |
| LLM + targeted true replay footage | Mechanics/visual context missing from telemetry | Footage not yet exportable; default 1FPS can miss contacts; video may show future | Conditional A/B test |
| Retrieval from high-rank 2v2 data | Realistic positioning, styles and candidate alternatives | Behavior != optimality; rank and similarity selection biases | Audit dataset, test later |
| Small learned possession/goal pressure model | Calibrated tactical state descriptor and risk proxy | Predictive xG != causal value of a hypothetical challenge | Pilot if fast, must beat simple baseline |
| Offline RL/bot critic/action model | Could rank feasible actions with an explicit objective | Reward hacking, sim-vs-human mismatch, absent control inputs, training cost | Research option, not first build |
| 5B video world model | Multimodal counterfactual visuals | Expensive, bot-sim data, visual quality != physical/tactical truth | Defer |

**Strong alternative worth consideration:** dispense with goal-probability value models initially. Ask expert reviewers to rank **action pairs** from the same t0, explain conditions under which their order reverses, and train a tiny preference comparator only after high agreement. This might yield more faithful coaching with far less data than trying to forecast a whole future game.

## 5. An inspectable decision graph (design, not implementation)

**Time boundary:** every item says `available_through_s <= t0` to be valid decision-time evidence. An event that can be timestamped earlier but recognized only later is NOT allowed into the t0 state. Keep raw source-timestamp, current row timestamp, and inference freshness separate.

Suggested compact packet:

    case_ref: randomized id; match_group: private salted group id
    focus: anonymized player id and team; replay_time_t0; match_clock
    observations: [{evidence_id, actor, x/y/z, velocity, heading,
                    boost: {value_or_null, source_age, quality},
                    observed_at, available_through, provenance}]
    context_before_t0: recent touch/pressure/possession intervals WITH origin/finality
    roles_at_t0: first/second man probabilities and uncertainty; teammate cover ranges
    ball_control: carrier candidate, alternative carrier/contested, confidence basis
    feasible_actions: [{id, route_family, earliest_touch_interval,
                        boost_budget, recovery_window, mechanical_requirements,
                        coverage/pressure tradeoff, uncertainty, source ids}]
    unknowns: analog player input, comms, actual intent, unobserved packets,
              opponent policies, post-commitment outcome
    retrospective: {observed_choice, after_t0_events}   # Firewalled, not t0 merit
    coach_claims: [{kind, statement, evidence_ids, alternatives, limits,
                    counterfactual_assumption, falsifier}]

The **single most important addition** is not a new number. It is **possible opponent responses** and whether a proposed decision is **robust across plausible reactions**. A high-level challenge might be reasonable even if a worse outcome happened, if it forces the opponent into constrained options and the teammate can recover. Conversely winning a 50 can be poor if almost every ball direction merely resets possession and leaves the attacker out of play. Require at least two opponent responses plus a plausible favorable aggressive scenario before condemning an aggressive choice.

Suggested read-only LLM tools:
- `get_window(case_ref, start, end, cutoff=t0)`: rejects post-cutoff requests in merit mode.
- `get_player_state(actor, at_t0)`: annotated provenance, invalid/unknown values exposed.
- `get_control_and_pressure(case_ref)`: possession candidates, control confidence, pressure histories.
- `get_reach_and_cover(case_ref, action_id)`: interval, possible modes, missing mechanics, cover.
- `enumerate_feasible_actions(case_ref)`: challenge, delay/shadow, retreat/support, fake/force only if grounded.
- `compare_opponent_responses(case_ref, action_ids)`: bounded scenarios, qualitative ranges, not guaranteed futures.
- `get_similar_expert_examples(case_ref)`: only after an audited high-rank dataset, with explicit "example not optimum".
- `get_retrospective_outcome(case_ref)`: available ONLY in post-judgment review or user follow-up; never authorizes a t0 merit rewrite without new valid t0 evidence.

Validation contract: (a) exact JSON schema, bounded calls, no tool execution without owner-specified tool allowlist; (b) every factual assertion references a real permitted evidence ID; (c) inferred or hypothetical claims use explicit modality, not certainty; (d) retrospective facts physically separate; (e) user dispute can request new predecision evidence and/or soften assessment; (f) human reviewer judges semantic support of claims. Test future-frame mutation invariance on ratings, plus deliberate missing-boost/missing-coordinate/false-intent adversarial cases.

## 6. Worked BACKBOARD decision — what the system actually knows

**Hypothetical example, not a measured replay:**

- Observed: at t0, our first player approaches a ball in an opponent's backboard zone; teammate and two opponents have positions/orientations and possibly boost.
- Estimated: reach time by each actor, opponent's possession/control (not the same as last touch), teammate recovery, threat lanes, candidate options. Assign sources and bounds.
- Hypothetical: an immediate challenge might force a favorable 50 OR let the opponent play around; a delayed shadow may preserve coverage OR permit more controlled possession. Model both favorable and adverse opponent responses. If the teammate is positioned to receive a forced 50, a favorable aggressive action must be permitted.
- Unknown: what the opponent would truly choose under the alternate action, teammate voice comms, exact steering/powerslide input, human execution reliability.
- Acceptable coach statement: "This challenge could consume much of your boost and leave a recoverability gap if the opponent plays past you; a delayed shadow appears defensible provided your teammate can cover the exit lane. A fast forced touch toward your teammate is also plausible; inspect whether that angle was available." 
- Unacceptable statement: "This challenge definitely caused a 1v2, and shadowing would certainly win possession" without actual temporal, coverage and causal proof.

## 7. Three decisive experiments for the strategic meeting

### Experiment A — Does a tool-using LLM really help?

**Input:** 8-12 difficult, independently selected 2v2 situations across >=4 complete replays, including positive plays, intentional lost 50s, risk, tradeoff and abstention cases. At least two independent experienced reviewers label t0 merit before seeing models. Keep a separate small holdout group.

**Compare on identical frozen evidence:** (1) Claude deterministic rule+reach output; (2) a single Gemini evidence packet without tools; (3) Gemini evidence packet WITH safe read-only tactical tools; optionally (4) second provider/model after permission. Each must deliver the same typed evidence and limited explanation budget.

**Measure:** reviewer sound/risk/tradeoff agreement, false criticism of SOUND, key decision recall, *claim-level* supported statements, decisive useful explanation, proper uncertainty, expert preference, per-case latency and tokens. Important: judge **usefulness and semantic support**, not eloquence. Randomize model labels and presentation order.

**Stop/go:** choose tool approach only if it improves blinded usefulness and/or supported factuality over the much simpler baseline without unacceptable false blame. Predeclare improvement thresholds with the owner and raters before opening results; do not fabricate a significance claim from 8-12 cases.

### Experiment B — Does adding calibrated possession/threat value improve decisions?

**Input:** same case packets, plus time-frozen advantage and goal-pressure estimates from an audited model vs simple distance/turn/race heuristics. Verify that the model has NO lookahead features and has acceptable held-out game calibration. Compare expert judgments with/without the feature under fixed text prompt.

**Stop/go:** if LLM explanations become more certain but NOT more correct/useful, reject the added value feature. A possession model's probability is NOT a causal estimate of proposed alternative success. Prefer a human action-preference labeling scheme if estimates aren't helpful.

### Experiment C — Can native playback and truthful video improve the judgment?

**Input:** an authorized user's local native Stats API replay control + genuine short video capture aligned at t0, *only after real game test and explicit permission*. Compare telemetry-only vs telemetry+pre-t0 visual frames. Native visual source is especially valuable for contact, ball carry, spin and complex mechanics.

**Measure:** media correctness, focus and time sync, image/frame freshness, model claims about mechanics, expert-rated explanation usefulness, privacy and API cost. Avoid post-t0 frames in merit scoring. Mobile fallback is independent rendered replay or a real precomputed source clip, never a one-frame placeholder.

**Stop/go:** if real footage adds little beyond cleaned telemetry or capture is too unreliable, native screen integration remains an optional viewer convenience, not a dependency for AI coaching.

## 8. Evaluation design, quality bars and failure suite

Do NOT claim broad accuracy from 15 replays, 5,783 correlated car moments, 40 timing clips, 636 candidate manifests or model JSON-validity passes.

Study A (40 clips): detect decision-time interval/choice. Study B (separate): expert labels `sound/risk/tradeoff/indeterminate` from PRE-t0 evidence, then blinded coach explanation ratings. Additional action-pair preferences can rank challenge vs shadow when BOTH are reasonable. Include sources not picked by our own detector to measure what we MISS. Split by complete match and ideally player/opponent groups; keep all variants of a replay in one partition. Count every abstention. Sample several distinct ranks and styles, not only one replay or all known mistakes.

Eight adversarial gates:
1. Player takes a poor challenge but gets lucky with a goal: don't praise just because of outcome.
2. Sound delayed challenge still concedes: don't blame due to outcome.
3. A deliberately lost 50 favors available teammate: don't equate first touch loser with bad.
4. A won backboard 50 gives away field possession and consumes boost: check value after contact, not "won" label.
5. Aggressive fake pressure forces opponent to surrender control: recognize valid aggression and restraint.
6. Teammate absent/demolished or unknown boost: admit uncertainty, don't invent positions/100 boost.
7. Suggested alternative requires mechanical capability beyond this player: don't assert feasible from a theoretical perfect turn.
8. Model receives later goal/score metadata or an almost-identical replay with swapped future: decision-time judgment invariant when ALL predecision evidence identical; explanation about post-outcome isolated. On player challenge ("we were in comms") update the assumption, not the recorded facts.

Research success = expert-rated, falsifiable coaching on withheld matches, no false-confidence disaster, user learns a concrete principle. Not number of flags or prose length.

## 9. Product and operating decisions

**Desktop now:** optional Rocket League native replay window + app 2D plus coach; native Stats API integration already in PR #20 but no verified live handshake. Independently test window control first. User's separate browser HD renderer remains available and mandatory long-term for phone. Both must use a shared canonical replay-time mapping with measured drift.

**Mobile later:** no game dependency; use preprocessed native replay data and independent 3D/2D playback where possible; opt-in cloud reasoning or private local mini-model fallback. Native precomputed clips can supplement but are not equivalent to freely explorable mobile 3D. Do not spend this wave rebuilding shader fidelity.

**Training:** do not train a large local LLM now. First sample/validate the 2v2 high-rank dataset, get high-quality expert action preferences, establish a learned SMALL classifier/ranker baseline, then consider fine-tuning if it improves held-out expert decisions and economics. A model that plays better than a human may still be bad at teaching.

**Privacy:** public GitHub contains only documentation, schemas and anonymized aggregate figures. Keep identities, replays, proprietary source clips, API credentials, private mappings and human ratings outside public git. Gemini consumer subscriptions do not automatically include paid API calls; require per-test consent/cost caps.

## 10. Ranked priorities if the strategic meeting approves

1. Correct the selected-window evidence bug and fix parser/provenance/unknown boost preconditions. Write decision-time typed evidence schema. This is a **prerequisite**, not product differentiation.
2. Assemble a small balanced human-labeled 2v2 "golden cases" set before optimizing Gemini prompts; conduct side-by-side evidence-only, tool-using and deterministic baseline assessment.
3. Test PR #20 native Stats API under owner-authorized local game; if native playback works, capture real private clips to enable targeted visual analysis and expert blind labels.
4. Audit a legal sample of the 49,658-match 2v2 corpus and candidate possession/xG implementation; test a small value feature on **different complete matches**.
5. Use the result to choose between LLM+tools, expert-preference comparator, goal-pressure signal, or a combined architecture. Continue reviewer-guided HD mobile fallback separately.

**Do not build next:** a comprehensive custom LLM training stack, a supposed exact physics future predictor, a 5B on-device video world model, a 200x complete-replay binary rewrite based on one-player tests, another cluttered analytics UI, or a huge model-generated list of "mistakes".

## 11. Meeting decisions and what would falsify my preferred path

**Questions to answer with the owner and other models:**
- What counts as genuinely useful coaching? One excellent novel lesson or multiple middling observations?
- Can two experienced 2v2 reviewers reliably rank alternatives from pre-t0 evidence, or are some decisions unobservable due to comms/intent?
- Does Gemini with tools outperform an honest no-tools baseline on blind cases, or does it only sound more convincing?
- Which model best represents possession and opponent response without claiming simulated counterfactual truth?
- Does the 2v2 high-rank corpus allow useful action-value learning, and are the data rights and source fields reliable?
- Can native Stats API control synchronize accurately and safely; can we capture game video without a mod?
- Which losses of accuracy or privacy are acceptable for optional phone/cloud support?

**Falsification criterion:** if tool-augmented LLM explanations are no more semantically sound or useful than carefully selected deterministic evidence briefs, then the LLM should be a QUESTION/TEACHING layer, not the tactical decision judge. If experts disagree heavily on the same t0 replay evidence, prioritize describing contingent tradeoffs and identifying missing information rather than training on artificial consensus. If a small model cannot improve independent held-out matches, keep it out of production. If native capture is flaky, avoid delaying the coach for it.
